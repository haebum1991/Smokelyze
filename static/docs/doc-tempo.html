NASA/TEMPO Satellite Retrieval

Last Updated: 2026-07-23

Retrieves high-resolution Tropospheric Vertical Column Densities (VCD) of NO2 and HCHO from the TEMPO (Tropospheric Emissions: Monitoring of Pollution) satellite. Unlike previous polar-orbiting instruments, TEMPO provides hourly observations across North America at a native (Level 2) spatial resolution of approximately 2.0 × 4.75 km2. In this application, the gridded Level 3 data (0.02° × 0.02°) is converted to 0.04° × 0.04° resolution and rendered on the map as PNG tiles.

1. Key Information

  • Purpose: Provide real-time, high-resolution trace gas concentrations for air quality monitoring and model validation.
  • Source: NASA EarthData - Atmospheric Science Data Center (ASDC).
  • Products: TEMPO_NO2VCD_L3_V03/04 and TEMPO_HCHOVCD_L3_V03/04 (Transitioned from V03 to V04 on Sep 16, 2025).
  • Refresh Rate: Hourly daytime scans across the Continental United States (CONUS), Canada, and Mexico.

2. Main Workflow

1API Query (CMR): Uses NASA's Common Metadata Repository (CMR) API to identify the latest Level-3 data granules by product and date.
2Cloud Authentication: Uses a custom .netrc configuration to authenticate with GES DISC and ASDC, enabling direct cloud access via vsicurl.
3Quality Filtering: Applies NASA's recommended masks: Quality Flag filtering (flag == 0) and Cloud Fraction exclusion (effective cloud < 0.1).
4Raster Processing: Merges multiple granules, aligns to the North American extent, and reprojects to EPSG:3857 (Web Mercator) for high-performance web mapping.
5Optimization: Encodes raw values into high-performance 8-bit grayscale PNG tiles and saves accompanying JSON metadata for on-the-fly value reconstruction.

4. Technical Implementation

- NASA EarthData CMR Query

Queries the CMR JSON API for specific collection IDs (NO2 or HCHO) and temporal ranges to retrieve HTTPS download links.

# Query CMR API for granules
params <- list(
  collection_concept_id = collection_id,
  temporal = paste0(target_date, "T00:00:00Z,", target_date, "T23:59:59Z"),
  page_size = 100
)
res <- httr::GET("https://cmr.earthdata.nasa.gov/search/granules.json", query = params)
nc_urls <- fromJSON(content(res, "text"))$feed$entry$links

- Direct Cloud Access via vsicurl

Leveraging GDAL's virtual file system, the pipeline processes NetCDF subdatasets directly from the NASA S3-backed HTTPS archive without locally downloading the files, significantly reducing execution time.

# GDAL HTTP Configuration
terra::setGDALconfig("GDAL_HTTP_NETRC", "YES")
terra::setGDALconfig("GDAL_HTTP_UNAUTH_AUTH", "BASIC")

# Load specifically the vertical column density and quality flag
prod_stack <- terra::rast(nc_url, subds = "/product/vertical_column")
flag_stack <- terra::rast(nc_url, subds = "/product/main_data_quality_flag")

# Apply Quality Mask (Flag 0 = Valid)
prod_stack[flag_stack != 0] <- NA

- High-Performance PNG Encoding

To enable fast delivery to the client, the floating-point raster is normalized to an 8-bit integer range (0-255) and stored as a compressed PNG. The min and max values are saved in an accompanying JSON metadata file, allowing the frontend to reconstruct the actual scientific values using the formula: Val = Min + (Pixel / 255) * (Max - Min). 

# Spatial Aggregation (0.02° -> 0.04°)
r_agg <- terra::aggregate(prod_stack, fact = 2, fun = "mean", na.rm = TRUE)

# Reproject to EPSG:3857 (Web Mercator)
r_proj <- terra::project(r_agg, "EPSG:3857", method = "bilinear")

# 8-bit Normalization
i_min <- min(values(r_proj), na.rm = T)
i_max <- max(values(r_proj), na.rm = T)
r_encoded <- (r_proj - i_min) / (i_max - i_min) * 255

# Save as PNG
terra::writeRaster(r_encoded, "tempo_no2.png", datatype = "INT1U", filetype = "PNG")
