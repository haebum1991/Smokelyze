Technical Stack & Architecture

Smokelyze is a cloud-native geospatial platform designed to monitor and analyze wildfire smoke impacts. It utilizes a three-tier architecture combining R-based data science with a modern, responsive web frontend.

Mission: Precisely quantify the impact of wildfire smoke on air quality (O3 & PM2.5) by disentangling smoke contributions from meteorological factors using advanced spatiotemporal modeling (GAM).

1. Frontend (Client-Side)

  • Static Site Generator: Hugo (Go-based) for high performance and SEO.
  • Interactive Maps: "MapLibre GL" with OpenFreeMap vector tiles and customized GeoJSON layers.
  • Data Visualization: "Plotly.js" for interactive temporal and statistical plotting (bar, line, scatter, etc.).
  • Real-time Interaction: "Firebase" for community MapPosts and opinion sharing.
  • Styling: Vanilla CSS and responsive layouts (Optimized for Laptop, Desktop & Mobile).

2. Backend & Data Pipeline (Server-Side)

The backend is built as a series of automated R pipelines running in a containerized environment (Docker), with real-time services powered by Firebase.

  • Runtime Engine: R Language (4.3+) specialized for GIS and statistical modeling.
  • Serverless Services (Firebase):
    • Authentication: Secure user sign-in and profile management.
    • Realtime Database: Instant syncing of MapPosts (user opinions/reports) across clients.
    • Cloud Firestore: Structured storage for Announcements and metadata.
    • Event Logging: Tracking user engagement and data pipeline execution status.
  • Core R Pipelines (Cloud Run Jobs):
    • fetch_wildfire.R: Integration of NIFC fire data and Google News RSS tracking.
    • fetch_airnow.R: Retrieval and processing of daily mean PM2.5 and MDA8 O3 monitoring data.
    • fetch_hms.R: Collection and processing of NOAA HMS satellite smoke and fire data.
    • fetch_smokeday.R: Data aggregation and processing tool for the Smoke Day identification.
    • fetch_merra2.R: Retrieval of NASA MERRA-2 meteorological variables (e.g., T2MAX, SRAD) for GAM-v2 predictors.
    • fetch_tropomi.R: Processing of Sentinel-5P TROPOMI trace gas densities (NO2, HCHO) for GAM-v2 predictors.
    • fetch_hysplit.R: Atmospheric back-trajectory modeling to derive transport path metrics for GAM-v2 predictors.
    • fetch_pred_gam_v2.R: Predictive modeling for Smoke O3 (2025+) using collected predictors and pre-trained GAM-v2 architectures.

3. Infrastructure & Storage

Component Technology Role
Source Control GitHub Version control and centralized repository for all project assets.
Web Hosting Netlify Global CDN hosting for the responsive Hugo-based frontend.
Real-time Services Firebase User Authentication, MapPost synchronization, and Event Logging.
Object Storage Google Cloud Storage (GCS) Binary storage for processed GeoJSON, RData, and high-res artifacts.
Analytics DB Google BigQuery High-speed data warehouse for spatial and temporal trend analysis.
Compute Google Cloud Run Serverless execution of Docker-encapsulated R pipelines.

4. System Data Flow

1Ingestion: Multiple R pipelines fetch raw data via NASA, NOAA, and EPA APIs.
2Processing: R-GIS (sf, terra) handles spatial joins, unit conversions, and GAM predictions.
3Aggregation: Processed results are synced to BigQuery (for analysis) and GCS (for delivery).
4Visualization: The client-side MapLibre GL engine renders light GeoJSON layers dynamically.
